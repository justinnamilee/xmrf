# Signed package repositories

The repository publisher consumes the release builder's packages. It does not
rebuild application code. It selects up to `REPO_SIZE` stable, published releases
(default 5, allowed 1–100), ordered by publication time. Older DEB/RPM-only
releases remain usable, but the newest selected release must contain all four
Linux formats. Publish a stable four-format release before the first run.
GitHub-provided SHA-256 asset digests are checked before signing when available;
older assets without digests remain supported. The site is rebuilt from scratch
on every run, so releases outside the retention window disappear.

## Required configuration

The `github-pages` environment and GitHub Pages source must already be configured
for GitHub Actions. Existing environment approval/branch rules still apply.
Signing secrets may be repository secrets or environment secrets exposed to the
build job. The deployment job alone receives `pages: write` and `id-token: write`;
build and test jobs have read-only repository access.

| Setting | Kind | Purpose |
| --- | --- | --- |
| `GPG_KEY_ID` | Variable, existing | Selects the existing private OpenPGP key |
| `GPG_PRIVATE_KEY` | Secret, existing | Armored OpenPGP private key |
| `GPG_PASSPHRASE` | Secret, existing | Passphrase; may be empty for an unencrypted key |
| `REPO_SIZE` | Variable, optional | Stable release retention, default 5 |
| `APK_PRIVATE_KEY` | **New secret** | Persistent, unencrypted RSA PEM private key |

The selected OpenPGP primary fingerprint must match the full fingerprint pinned
in `public/install/install.sh` (currently
`77EB2650F7CFEC5B6585A2FD33465E81997C2758`). The same identity signs APT metadata,
RPM packages and metadata, Arch packages/databases, and the Alpine RSA public key.

Generate the Alpine key once on a trusted machine:

```sh
umask 077
openssl genrsa -out xmrf-alpine.rsa 4096
gh secret set APK_PRIVATE_KEY --env github-pages < xmrf-alpine.rsa
```

Keep a secure backup. Never commit this file or put it in a release asset. Do not
generate a new key on each workflow run. The public key is derived during
publishing and its name remains `xmrf-alpine.rsa.pub`, as required by APK's index
signature lookup. Rotating the RSA key requires existing clients to rerun the
installer before they can verify indexes made with the replacement key. Rotating
the OpenPGP primary identity additionally requires an explicit trust-pin update.
Private files and the temporary GPG agent are removed by the signing script's
exit trap; signing secrets are exposed only to the signing step.

## Published layout and verification

| Path | Contents and authentication |
| --- | --- |
| `/deb/pool/main/` | Architecture-independent DEBs |
| `/deb/dists/stable/` | Signed `InRelease` and `Release.gpg`, with actual indexes for every advertised architecture |
| `/rpm/` | GPG-signed noarch RPMs and signed `repodata/repomd.xml`; clients require both |
| `/apk/noarch/` | Canonical noarch APKs and RSA-SHA256-signed `APKINDEX.tar.gz` |
| `/apk/<native-arch>/` | Copies of the same noarch payload for APK's automatic architecture URL selection |
| `/arch/any/` | GPG-signed `any` packages, signed `xmrf.db` and `xmrf.files`, plus their `.tar.gz` forms |
| `/xmrf-signing.asc` | Existing OpenPGP public key |
| `/xmrf-alpine.rsa.pub` | Alpine RSA public key |
| `/xmrf-alpine.rsa.pub.asc` | OpenPGP signature authenticating the RSA public key |
| `/releases.json` | Retained release tags and canonical package paths |
| `/build-id.txt` | Workflow run/attempt ID used to check live deployment freshness |

Alpine release assets from nFPM are renamed to `xmrf-<pkgver>.apk` so that APK can
fetch the filenames requested by its index. The signed index authenticates each
package's control checksum, which in turn authenticates its payload hash. These
APKs are not independently signed for arbitrary local-file installation; install
through the signed repository. The publisher's `apk index --allow-untrusted`
accepts unsigned input **only while generating** that index. Neither the public
installer nor the repository smoke tests use trust-bypass flags.

The Alpine directory copies cover x86_64, aarch64, armhf, armv7, x86, ppc64le,
s390x, riscv64 and loongarch64. The package is Perl-only; native installation is
tested on x86_64. Arch uses one architecture-independent server directory instead
of separate CPU directories. `repo-add --prevent-downgrade` indexes the newest
package version while retaining older package files. Symlinks generated by
`repo-add` are replaced with real files for GitHub Pages.

RPM signing changes the downloaded RPM bytes. GitHub Release checksums describe
the original release assets; repository metadata describes the signed copies.
The existing Ansible repository playbook still targets DEB/RPM only.

## Installers

`public/install/install.sh` is the sole installer source. Publishing serves
identical copies at `install.sh`, `install-apt.sh`, `install-dnf.sh`,
`install-apk.sh`, and `install-pacman.sh`. Old APT/DNF URLs keep working. Each URL
auto-detects the distribution rather than forcing a particular package manager.
No Bash dependency is introduced on Alpine.

```sh
curl -fsSL https://xmrf.taiz.me/install.sh -o install.sh
less install.sh
sudo sh install.sh
```

On Alpine, use `wget -O install.sh https://xmrf.taiz.me/install.sh`, review it,
then run `sh install.sh` as root. Root privilege is required; the script does not
install sudo or doas. Arch installation performs `pacman -Syu` to avoid a partial
upgrade. Unknown distributions fail with a clear message; recognized derivatives
use `/etc/os-release`'s `ID_LIKE` family. Rerunning updates the same managed
configuration without duplicating source entries.

The installer verifies the OpenPGP fingerprint in an isolated temporary keyring.
Alpine additionally verifies the RSA public key's OpenPGP signature. Arch imports
and locally signs the verified key with `pacman-key`; both package and database
signatures are mandatory for the XMRF repository. APT scopes trust through
`Signed-By`; DNF enables both `gpgcheck=1` and `repo_gpgcheck=1`. Existing system
repositories keep their own trust settings.

The default URL is `https://xmrf.taiz.me`. For another HTTPS mirror or an offline
local mirror, set `XMRF_REPO_URL` explicitly. Only HTTPS and absolute `file://`
URLs are accepted. This is also how CI exercises the exact installer before
publishing; there is no insecure HTTP testing option.

## Workflow gates and validation

1. **Build:** after Python/shell checks, download release assets,
   import and validate keys, sign packages/indexes, and archive one immutable
   Pages artifact. The RSA container sees only its RSA key; the Arch indexing
   container receives no private keys.
2. **Test:** on clean Debian 13, Fedora 44, Alpine 3.24 and Arch containers,
   install using the signed local repository, run the installer again, and verify
   CLI help/version, dry-run behavior and an actual rename. Each client must then
   reject a mirror containing modified APT/RPM metadata or an unsigned APK/Arch
   index. These negative controls prevent an accidental verification bypass from
   looking like a successful installation test.
3. **Deploy:** deploy that same artifact only after all four tests pass.
4. **Live:** wait for the expected build ID, download the deployed installer over
   HTTPS, and repeat installation/runtime checks on all four distributions.
   A failure here is reported after deployment; it does not automatically roll
   back the site.

Publication runs on stable release publication or manual dispatch. Matching pull
requests run only unit tests and shell checks, without signing secrets.
Prerelease events do not republish the stable repositories. Action references and
container manifest digests are pinned. Existing Dependabot configuration covers
Actions; inline Docker image digests need deliberate updates. Linux mirrors and
native tooling packages still receive signed upstream updates.

Local checks, without signing keys or Docker:

```sh
python3 -m unittest discover -s .github/scripts/tests -v
actionlint
shellcheck public/install/install.sh .github/scripts/build-repositories.sh \
  .github/scripts/run-repository-test.sh .github/scripts/test-repository.sh
```

The full signing/installation tests require the configured secrets and a Docker
runner; they never use production private keys in unit tests.
